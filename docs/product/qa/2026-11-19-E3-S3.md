## Code and security review

No findings. All raw SQL goes through Drizzle's parameterised `sql`, and every input is validated with zod. Each mutation locks its row, and the version checks stop silent overwrites.

Accepted decisions:
- The current Stage is stored as a position number.
- Each Task has its own version, and a no-op edit writes nothing.
- A start on an archived Prospect reuses `prospect_archived`.
- Changing the Funding Officer is refused on Won and Lost.

Process note from the builder: the tests were written in one batch rather than strictly test-first. One real defect, a missing `outcome` message, was found and fixed.

## Change after the user's decision (2026-11-19)

The brief's EC19 and E3-S3 #8 disagreed about On Hold. The user chose the brief, so only an open Pipeline blocks archiving. Changed:
- `archiveProspect` now checks only `outcome IS NULL`.
- Resuming an On Hold Pipeline (On Hold → Open) now refuses when its Prospect is archived, so no open Pipeline can exist on an archived Prospect.
- The criterion 8 tests were rewritten (the On Hold case failed before the change), and the backlog, `api.md` and this report were updated.

Re-run after the change: `tests/unit/E3-S3.test.ts` 51 of 51, plus the full suite below.
