# QA report: E0-S3 Admin sign-in

Date: 2026-11-19. Tester: tester skill under `/develop` (planner-v1). Branch `feature/planner-v1`. Local Postgres 16 in Docker.

Unit tests are in `tests/unit/E0-S3.test.ts`, and end-to-end tests in `tests/e2e/E0-S3.spec.ts` (mobile, tablet, desktop).

| # | Criterion | Tests | Result |
|---|-----------|-------|--------|
| 1 | Seed script creates or updates an Admin; password stored only as a strong hash | hash format and parameters (scrypt N=2^15, r=8, p=1, 16-byte salt, 64-byte key); the real script creates, then updates, the same row; the stored hash verifies and the password is absent from the database and the output; refuses a bad email, no password, or a short password. The password comes from `ADMIN_PASSWORD` or a prompt, never from the arguments (ADR 0002). | Pass |
| 2 | httpOnly, Secure in production, SameSite=Lax cookie, 30 days | Set-Cookie has HttpOnly, SameSite=Lax, Path=/ and Max-Age=2592000, with no Secure outside production and Secure under `NODE_ENV=production`; the database stores only the SHA-256 of the token; the session expires in 30 days | Pass |
| 3 | Wrong email and wrong password give the same error | byte-identical 401 bodies ("Email atau kata sandi salah."), no cookie, and the dummy scrypt runs for unknown emails | Pass |
| 4 | 5 failures in 15 minutes lock the email for 15 minutes, even with the right password (EC41) | the 6th attempt gets 429 even with the right password; counted per normalised email; an unknown email gets the same 429; still locked at 14 minutes and unlocked at 15m01s; a success clears failures; 12 parallel guesses give exactly 5 × 401 and 7 × 429 | Pass |
| 5 | Every API route except sign-in and health answers 401 without a valid session (EC39) | every `route.ts` under `src/app/api/` is called with no cookie, a forged cookie and an expired session, and all get 401; the proxy gives 401 JSON for `/api/*` and redirects pages to `/masuk?next=…`; public paths are exact matches; E2E: a signed-out visit to `/` lands on `/masuk?next=%2F`, and `/api/auth/me` gives 401 | Pass |
| 6 | Sign-out ends the session on the server | 204, the cookie is cleared and the row deleted, and the old cookie then gets 401; other sessions survive; a cross-origin sign-out gets 403; E2E sign-in → `/me` 200 → sign-out → `/me` 401, and replaying the old cookie also gets 401 | Pass |

Not automated: the interactive hidden password prompt of the seed script needs a terminal. Its refusal without a terminal and without `ADMIN_PASSWORD` is tested.

## Responsive checks

E0-S3 is a backend story. The placeholder `/masuk` page (replaced in E0-S5) passed the existing E0-S1 checks at all three viewports, including no horizontal scroll.

## Code and security review

- Two deviations from the build brief were accepted:
  - Sign-out without a valid session answers 401, which follows ADR 0002 and criterion 5.
  - `toErrorResponse` rethrows Next.js control-flow errors, so routes that read the request are not logged as failures at build time.
- Security review: no findings. Accepted by design (ADR 0002): someone who knows the Admin's email can lock that account for 15 minutes.
