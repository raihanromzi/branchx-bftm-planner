## Code review

No findings. Actual is computed on read, never stored. The Task Overdue rule now lives in one function, `isTaskOverdue`, which `getPipeline` uses, and `listOverdueTasks` mirrors it in SQL. `setTarget` locks the row, and a concurrent first insert falls back to 409 through `onConflictDoNothing`. All SQL goes through Drizzle's parameterised builders.

Builder decisions accepted, because they are within the criteria and the design:
- The endpoint is `PUT /api/targets`, with `version: null` for "no Target yet". It needs no Idempotency-Key, because it is an upsert. Sending the value already stored is a no-op.
- An inactive Funding Officer cannot be given a Target. The lists show every active Funding Officer, plus an inactive one only when it has a Target or Actual that month (design E5-S3).
- The team Target is null only when no Funding Officer has a Target that month.
- The overdue lists, upcoming Activities and Pipelines by Stage always describe now, whatever month is chosen.
- Upcoming Activities include every status. Whether "7 hari ke depan" should hide Cancelled ones is left to E5-S3, which can filter by `status`.
