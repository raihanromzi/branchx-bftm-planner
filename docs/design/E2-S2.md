# E2-S2 Prospect list

## Task

The Admin finds a Prospect fast (by name, Category or Funding Officer) and sees where each one stands, mostly on a phone between visits.

## Priority of content

1. Prospect name
2. Stage of the open Pipeline (or none)
3. Funding Officer
4. Category, location status
5. Search, then filters
6. "Tambah Prospect"

## Layout

**Mobile (360):** under the top bar, a sticky search field (full width, `Search` icon, 48 px). Below it, a row of filter chips that scrolls horizontally inside its own box: "Kategori", "Funding Officer", "Tampilkan arsip". Then the list as rows separated by borders (not floating cards):

```
┌──────────────────────────────┐
│ Prospect                     │
│ [🔍 Cari nama Prospect     ] │
│ (Kategori ▾)(Funding Officer ▾)(Arsip)
│ 1.248 Prospect               │
├──────────────────────────────┤
│ SDN 3 Cibinong               │
│ [●●●○○ Presentasi]           │
│ Sekolah, Rina Kartika        │
├──────────────────────────────┤
│ Pasar Kramat Jati Blok B     │
│ Belum ada Pipeline           │
│ Pasar, Agus Setiawan         │
│ ⌖ Belum ada lokasi           │
├──────────────────────────────┤
│        ‹  1 / 25  ›          │
│                  [+ Tambah]  │
└──────────────────────────────┘
```

The meta line joins Category and Funding Officer with a comma. Each row is a link to the detail page, at least 72 px high. The pager sits at the bottom with "Sebelumnya" / "Berikutnya" and "Halaman 1 dari 25".

**Tablet (768):** the same as mobile, with the filters on one line without scrolling.

**Desktop (1280):** the page header has the title, the result count ("1.248 Prospect") and "Tambah Prospect". A filter bar holds the search (320 px) and three selects. Then a table:

| Nama | Tahap | Funding Officer | Kategori | Potensi rekening | Lokasi |
|------|-------|-----------------|----------|------------------|--------|

Rows are 44 px; numbers are right-aligned with tabular figures. "Lokasi" shows "Ada" or "Belum ada". The name cell truncates to one line with the full name in a tooltip on hover and focus. The pager is below the table on the right.

## States

- **Empty (no Prospects at all):** "Belum ada Prospect. Prospect adalah sekolah, pasar, perusahaan, atau instansi yang ingin dibukakan rekening oleh tim Anda." with "Tambah Prospect".
- **No results:** "Tidak ada Prospect yang cocok dengan \"kramat\"." with "Hapus filter".
- **Loading:** eight skeleton rows shaped like the rows; the search keeps its value.
- **Error:** "Daftar Prospect gagal dimuat. Periksa koneksi, lalu coba lagi." with "Coba lagi".
- **Normal:** 50 rows per page. Realistic data: "SDN 3 Cibinong", "Pasar Kramat Jati Blok B", "PT Sinar Logistik Nusantara", "Kantor Kecamatan Tanah Sareal", "Paguyuban Pedagang Pasar Anyar Kota Bogor".

## Edge cases

- EC6: paged at 50, search debounced at 300 ms, filters and page in the URL (`?q=&kategori=&fo=&arsip=1&hal=2`).
- EC7: a 150-character name wraps on mobile; truncated with tooltip on desktop.
- EC34: "Belum ada lokasi" with `MapPinOff`.
- EC45: the Stage badge never truncates below 12 characters; it wraps to its own line on mobile.
- Archived rows (when "Tampilkan arsip" is on) show a "Diarsipkan" outline label and muted name.
- E1-S4: an inactive Funding Officer shows "Funding Officer nonaktif".

## Accessibility notes

- The search has a visible-to-screen-reader label "Cari Prospect".
- The result count is in an `aria-live="polite"` region.
- Truncated names in the table keep the full name as the link's accessible name.
